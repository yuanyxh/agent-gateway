# 项目教训

## 格式

### <日期> <一句话标题>

- **场景**：发生了什么。
- **事实**：日志、测试或复现证据。
- **决策**：之后怎么做。
- **范围**：仅本项目 / 本技术栈 / 可能通用。
- **晋升**：未评估 / 已提议 / 已确认。

## 规则

- 只记录有证据的经验。
- 与已有条目重复时合并，不新增同义条目。
- 标记为“可能通用”的条目，需经用户确认才可写入种子库。

## 条目

### 2026-10-26 uvicorn 进程收到 SIGTERM 后不返回调用方

- **场景**：服务端把运行时状态文件的清理写在 `main()` 的 `try/finally`，退出后文件残留。
- **事实**：独立探针运行 `uvicorn.run(...)` 并在 finally 打印，SIGTERM 后探针从未打印；日志显示应用已优雅关闭。
- **决策**：生命周期清理放进 Starlette lifespan 的 shutdown 钩子；读取侧保留 PID 存活校验兜底。
- **范围**：可能通用（所有 uvicorn 常驻服务）。
- **晋升**：未评估。

### 2026-10-26 批量格式化会波及无关文件

- **场景**：给 `ruff format` 传入整个包目录，重排了 37 个未修改文件。
- **事实**：`git status` 出现大量与本任务无关的变更。
- **决策**：只格式化本次改动涉及的路径；批量格式化单独作为提交。
- **范围**：可能通用。
- **晋升**：未评估。

### 2026-10-30 检索工具“看起来相关”可能来自分数继承而非命中

- **场景**：`recall` 返回大量弱相关记忆，但结果里的路径/函数名足以让模型继续操作。
- **事实**：随机串 query 仍返回 0.554–0.564 的热层结果；episode 扩展把 sibling 分数写成 `seed*0.98`，实际相似度只用于排序；107 次历史 recall 中 19 次含 expanded，最多占 6/10。
- **决策**：相关性下限与扩展分数必须分别建模；扩展结果使用实际相似度并单独放入 `related`，不参与主结果排序。
- **范围**：可能通用（所有带 group expansion 的向量召回）。
- **晋升**：未评估。

### 2026-10-30 向量库分数是 numpy 标量，不能直接进 JSON

- **场景**：recall 改造部署后，冷层命中查询返回 `Object of type float32 is not JSON serializable`。
- **事实**：140 次批量调用中 27 次失败，全部来自冷层/扩展分数；`json.dumps` 不接受 `numpy.float32`。
- **决策**：Qdrant/mem0/余弦计算结果写入响应前统一 `float()`；回归测试断言返回类型是 Python `float`。
- **范围**：可能通用（所有 numpy 向量库输出）。
- **晋升**：未评估。
