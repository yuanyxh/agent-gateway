# 数据完整性规则

## DATA-01 自动化输入必须用原始正文

**规则**：LLM 判断、质量门、分组、矛盾检测、合并、语义过滤与评估标注的输入，必须来自原始正文（mem0 `data`、文件全文、API 原始响应）。图库 `title`、搜索 `snippet`、摘要切片等派生短字段只能用于展示。

**禁止**：用派生短字段作为判断依据；派生层缺正文时静默回退到更短字段。

**验证**：测试断言判断输入来自原始正文字段，并在降级时返回 `degraded` 标记。

## DATA-02 截断必须显式且可验证

**规则**：任何 `[:N]`、`max_chars` 截断必须定义命名常量，写明来源字段、上限、超限行为，并在日志或响应中标记 `truncated`。

**禁止**：匿名数字切片；截断后不标记，让调用方误以为拿到全文。

**验证**：测试覆盖超限输入，断言保留长度与 `truncated` 标记。

## DATA-03 派生数据不缺字段

**规则**：图库、索引、缓存等派生存储必须与源字段同步；白名单新增字段时同时给出历史回填或降级策略。

**禁止**：白名单静默丢字段；缺失字段时回退到更短字段而不告警。

**验证**：抽样比对派生存储与源正文长度；缺失率大于 0 时记录告警。

## DATA-04 自动化链路输入审计

**规则**：新增或修改自动化链路前，检索 `title`、`snippet`、`[:N`、`max_chars`、`truncat`，逐项列出截断字段、上限、用途与风险；评审必须包含输入完整性检查。

**禁止**：未审计截断来源就合并自动化改动。

**验证**：计划或交付摘要附审计清单，标明哪些输入来自原始正文、哪些属于预算截断。
