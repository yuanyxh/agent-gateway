# 召回可命中性治理（2026-11-19）

## 背景

全时段会话复盘与真实 trace 显示：recall 空率按周 0%→6.2%→8.8%→20.0%→22.5%，返回条数 8.08→5.20。
根因分三类：精度优先演进的必然代价、floor 拒绝无兜底、查询形态敏感；另有实例退化与热层懒加载竞态。

依据：本仓 `master` 上关于 `filter_fallback` 只覆盖维度过滤的代码事实；11-11 本地推理长查询空、单词命中。

## 目标

1. 真实 recall trace 可观测：每臂 raw 候选数、floor 拒绝数、维度过滤数、最终 count。
2. 命中不依赖查询形态：长 query 与 keywords-only 取并集，语义失败可用单关键词兜底。
3. floor 拒绝的候选可回填，弱匹配显式标注，不静默丢弃。
4. 评估 hot floor 0.616 与 0.55 的空率/准率差异，给出数据而非直接改默认。
5. 消除进程启动首次 recall 的热层竞态。

## 非目标

- 不改嵌入模型、不重建向量库、不调整 rerank 模型。
- 不修改 gate 的三态语义（ok / weak_match / no_match）。
- 不做评测集重标注。

## 验收

全部满足才算完成：

- 单元测试与全量测试通过；ruff format/check 通过。
- 真实查询集在隔离环境（临时 GATEWAY_HOME/GATEWAY_CACHE、记忆库副本、独立端口）跑通。
- 形态矩阵全部有记录（见下），每类至少 3 条查询，结果人工判定相关/不相关。
- 回归：同一查询集在改动前后对比空率、命中数、p95 延迟；空率下降且延迟不超 3s。
- trace 中可直接读到 `arm_raw`、`floor_rejected`、`filtered`、`count`。

### 形态矩阵

| 维度 | 取值 |
| --- | --- |
| 查询形态 | 长自然语言句；keywords-only；query+keywords；单词 keywords；短标识符 |
| 语言 | 中文；英文；中英混合 |
| 内容类型 | 业务事实；历史决策；符号/文件名；实体名；新主题（无内容） |
| 维度 | 不传 project；传 project；project 缺失记录；传 ticket/language |
| 层 | hot 命中；cold 命中；notes 兜底；仅 related |
| 异常 | 热层初始化竞态；空结果；维度过滤全剔；floor 全拒 |

## 步骤

1. P0-a：`ArmResult` 增加统计，三臂记录 raw/floor 拒绝；pipeline trace 透出。
2. P0-b：`Query` 增加 `terms`；pipeline 增加单关键词变体，与 primary/semantic 走 RRF 融合，按需触发。
3. P1-b：arm 保留 floor 拒绝的弱候选，strict 不足时按分数回填并标 `floor_fallback`，gate 判 weak_match。
4. P1-a：脚本对比 floor 0.616/0.55/0.50 的空率与命中数，产出记录。
5. P2：MCP 启动后台预热热层，或首次 recall 等待初始化完成。
6. 测试与端到端实证，更新 status 与决策日志。

## 验证结果（2026-11-19，隔离环境）

环境：`/tmp/recall-e2e/`，两份记忆库副本、独立端口（9011 新 / 9012 旧）、独立 cache；18 个样本 × 4~5 种形态，共 74 次调用。

| 版本 | 预期命中率 | 无内容样本命中率 | p50 延迟 |
| --- | --- | --- | --- |
| 改动前（旧 wheel） | 82.8% | 18.8% | 2492 ms |
| 仅多路变体 | 82.8% | 18.8% | 3057 ms |
| + floor 0.55（评估） | 86.2% | 18.8% | 3085 ms |
| + rerank 兜底 | 94.8% | 25.0% | 3364 ms |
| + 按需 term（最终） | 94.8% | 25.0%（修正标注后 0%） | 2899 ms |

- 回归：改动前后无一条"原来命中现在变空"。
- 修正标注后，无内容样本（量子纠缠、火星基地、随机串）命中为 0；此前 25% 全部来自标注错误的 `porting-history`（库内有 2026-09 移植教训记忆）。
- 额外发现并修复：rerank 负分丢弃无兜底（导致整条查询返回空）、SemanticArm 子串误匹配（`en` 命中 `nonexistent`，让随机串召回 10 条）。
- 已知限制：短标识符 keywords 形态（`getSafeAreaInset`）仍空，长 query 形态可命中。

## P0 校准实证（2026-11-19）

- 全量正文自检索分数恒等 1.0：冷层 1297 条 `self p50 = 1.0`；抽样 `stored vs fresh cosine = 1.0000`。热层同模型、同向量路径，结论相同。
- 因此"全量正文 + 中位数"得到的 floor 约为 1.0，真实查询（0.48-0.72）会全部被拒。原方案不可行。
- 20 字探针并非随意截断：它让自检索不再是恒等映射。但探针分布与真实查询分布不匹配，旧 floor 0.616/0.569 同样作废。
- 替代：用 `tests/eval/datasets/queries_gold.jsonl` 的 249 条完整查询，按 trace 中 dense 臂的原始分数做全量阈值扫描（F1 最优）。

## 冷层切块实测（2026-11-19，隔离副本）

- 1297 条冷记录按 400 字/80 重叠切为 5675 块（4.38 块/条），对 gold 249 条完整查询做父记录聚合召回。
- 排除 stale 后的可达相关标注 207 次：@10 0.531→0.551（+2.0pp）、@20 0.657→0.681（+2.4pp）、@40 0.812→0.807（-0.5pp）；MRR 0.450→0.439。
- 相关记录排名：1 名 48、2-10 名 90、11-40 名 65、41-100 名 27、>100 名 23。瓶颈是排序与语义区分度，不是摘要内部稀释。
- 切块后 40 条候选约只覆盖 9-20 个父记录（同父多块），父覆盖下降，抵消了块级精度收益。
- gold 379 个标注 id 中仅 141 个存在于冷层（16 个 stale），其余为热层、notes 或已不存在；绝对召回受标注可达性影响。
- 结论：切块重建收益约 2pp，代价是存储 4.4 倍与写入/删除/重建全链路改造，不建议实施。

## cold floor 隔离验证（2026-11-19）

- 生产 trace 315 条：cold arm 调用 211 次，101 次有候选，floor 拒绝 4508/4520（99.7%），93 次全灭；最终含 cold 仅 10 条（3.2%）。
- 隔离环境设 hot 0.616 / cold 0.50 / expanded 0.50，notes_semantic 保持 0.37：
  - 冷层最终出现率 3.2% → 24.3%（最近 148 条 trace 中 36 条）；cold kept>0 从 8/211 升到 67/202。
  - 形态矩阵 74 次：预期命中 95.2%（基线 94.8%），空样本集合与基线完全一致，零回归。
  - 无内容样本命中 0（更换真实随机串、保持 notes_semantic 后）。
  - p50 2709ms（基线 2899ms）；max 14.9s 来自无内容样本，基线 13.5s 同源。
- 结论：冷层可用性的瓶颈是 cold floor，不是融合或切块；降 cold 到 0.50 即可让候选进入融合。生产阈值未改，待确认。

## 维度过滤回填与冷层 project（2026-11-19）

- 生产复现：同一查询带 project 后 `filtered=10`、`count=0`；dense_hot kept 7、dense_cold kept 3 全部被维度过滤。
- 根因：filter_fallback 候补在 rerank 全负时被丢弃，原兜底只复活 strict 行。
- 修复：rerank 丢弃后同时复活 filter_fallback 行；新增失败测试，877 例通过。
- 冷层 project：1297 条全空；从 source_memory_ids 仅能推导 16 条（774 条无来源、414 条冲突），从 source_file 可推断 573 条（44%）。
- 写入侧补 source_file 推断；隔离写入验证冷层直接命中且无 filter_fallback。
- 隔离回填 573 条后，agent-gateway 冷层样例带 project 查询直接命中。
- 生产代码已部署（11-19 14:18 wheel + MCP 重启）；用户决定不做历史 573 条回填，仅新写入推断。dry-run 备份 `/tmp/recall-e2e/cold-project-backup.json`。
